The verify-first rule

For every install step: check the version first. Only install if the command returns "command not found". This avoids the install-failure rabbit hole that ate 20 minutes for SJ.

01Open Terminal
Spotlight → "Terminal" → enter.

Bri may have iTerm2 or Warp instead — any of them work. Native Terminal is fine.

02Check what she already has
Apple Silicon Macs with developer tools often have most of this. Verify first.

Run all five in order. Each returns either a version number or "command not found".

git --version
gh --version
python3 --version
brew --version
trash --version
Expected on most Macs: git installed (often 2.39+, came with Xcode CLT). brew likely installed if she's developer-adjacent. gh, python3, trash less likely.

Make a mental note of which returned a version and which said "command not found".

03Install Homebrew (only if Step 02 said "brew: command not found")
Homebrew is the Mac package manager. Without it, the other installs need manual workarounds.
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

This prompts for her Mac password (sudo) and takes ~3-5 min. After it finishes, the installer prints two lines to add brew to her PATH — run them exactly as shown (something like echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> /Users/<her>/.zprofile then the eval).

Verify:

brew --version
If something goes wrong here Most common: Xcode Command Line Tools missing. Brew installer will offer to install them — accept, takes ~10 min. If brew install fails completely, ping me. Don't push through.
04Install the missing prereqs (only the ones Step 02 marked as missing)
gh CLI for cloning, python3 for the vault search tool, trash for safe deletes (LESSONS L02).

For each command that returned "not found" in Step 02, run the matching line. Skip the ones already installed.

brew install gh                # only if `gh --version` failed
brew install python@3.12       # only if `python3 --version` failed
brew install trash-cli         # only if `trash --version` failed

Each takes 30-90 sec. Re-verify:

gh --version
python3 --version
trash --version
All three should report a version. If any still fail after install, that's unexpected — ping me before continuing.
05Sign Bri into GitHub via gh
She'll be the one with permissions on her local copy of the repo.
gh auth login

Walk her through these answers:

  • "What account?" → GitHub.com
  • "Preferred protocol?" → HTTPS
  • "Authenticate Git with your GitHub credentials?" → Yes
  • "How would you like to authenticate?" → Login with a web browser

Copy the one-time code shown in terminal. Press Enter. Browser opens to GitHub. She pastes the code, signs in if not already, authorises. Back in terminal, it confirms login.

Verify:

gh auth status
Should show: Logged in to github.com account <her-github-username>.
06Clone the repo to her Documents
Putting it in Documents keeps it findable. ~/projects works too if she prefers.
cd ~/Documents
gh repo clone ferrisbueller92/rallee-starter rallee-vault
cd rallee-vault

The folder is now at ~/Documents/rallee-vault. ~25MB.

Bri should be in the folder. ls shows README.md, SOUL.md, CLAUDE.md, .claude/, resources/, etc.
07Activate the config templates
The repo ships .example versions. Both copies are gitignored — her secrets stay local.
cp .claude/settings.example.json .claude/settings.json
cp env.example .env

That's it. The hooks now load when Claude Code opens the folder.

08Install Python dependencies
Powers the vault search tool. Skip if Bri doesn't want the semantic-search demo today — vault_search.py falls back to keyword grep without these deps.
pip3 install -r requirements.txt

Takes ~2-3 min. Downloads sentence-transformers (~80MB).

If pip fails with "externally-managed-environment" Common on newer macOS. Two options: (a) pip3 install --user -r requirements.txt, or (b) skip the install entirely — keyword fallback works fine for tomorrow. Don't burn time.
09Open the folder in Claude Code
This is the moment everything comes alive.

Launch Claude Code on her Mac. File → Open Folder → navigate to ~/Documents/rallee-vault. Confirm.

Claude Code loads .claude/settings.json automatically. Skills and hooks are now active only inside this folder. When she switches folders later, this workspace goes dormant.

Then: "Save this to my USER.md and remember it for every future session."

Claude reads SOUL/CLAUDE/USER on every session start (the session-state hook). After this, she never re-introduces herself.

First "oh, this is different from Claude Chat" moments. Pick the ones most relevant to her current work.
