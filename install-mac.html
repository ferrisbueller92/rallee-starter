Mac install runbook for Bri

Bri has no GitHub account and has never opened Terminal. The cleanest path: you do the setup, AirDrop the working folder to her Mac, open it in her Claude Code, demo. Zero Terminal for her. ~20 min total.

For: Dave (you) Bri's prerequisites: Mac + Claude Code installed Time on her Mac: ~15 min Updated: 2026-05-12 AEST

The plan in one paragraph

You clone the repo on your Mac in advance (5 min). You arrive at Bri's. You AirDrop the folder from your Mac to hers. She drags it into Documents. You open the folder in her Claude Code. She types an introduction to populate USER.md. You demo the four core skills together. Done. No GitHub account, no Terminal, no install on her side beyond what's already there.

What gets skipped (and why it's fine)

Python deps for the vault search tool — skip tomorrow. Vault search isn't critical for the demo; if Bri wants it later, you can install it then. Her starter works fully without it.

GitHub Desktop setup for self-service updates — skip tomorrow. When she's ready for updates herself (week 2+), we add it as Phase 2. For now, you re-AirDrop when there's something new.

Before the meeting (do at your Mac, 5 min)

PRE 01Confirm you have a fresh cloneYour Mac
Your local copy may be stale or have extra files. Get a clean one.

Open Terminal on your Mac:

cd ~/Downloads
gh repo clone ferrisbueller92/rallee-starter rallee-vault-for-bri
cd rallee-vault-for-bri

You now have a clean copy at ~/Downloads/rallee-vault-for-bri. ~25MB.

PRE 02Activate the config templates (so they ship working)Your Mac
The repo ships .example versions. If we pre-activate them, Bri's copy works immediately when she opens it — no config step on her side.
cp .claude/settings.example.json .claude/settings.json
cp env.example .env

Both files are normally gitignored, but they're now in the folder you're about to AirDrop, so they travel with it. No secrets in either — they're blank templates.

PRE 03Optional: zip the folder for AirDrop reliabilityYour Mac
AirDrop can occasionally drop files in deep folder structures. A zip is one item, transfers cleanly.

In Finder: right-click rallee-vault-for-bri → Compress. You get rallee-vault-for-bri.zip.

You can also just AirDrop the folder directly — both work. Zip is safer for reliability.

At Bri's Mac (~15 min)

01Confirm Claude Code is installed and workingHer Mac
She said she has it. Verify it opens before doing anything else.

Launch Claude Code on her Mac (Spotlight → "Claude" → Enter, or click the icon in Applications). Confirm it loads. Close it for now.

If Claude Code isn't installed Send her to claude.ai/download to install the desktop app. ~3 min. Or use the VS Code extension if she already has VS Code.
02AirDrop the folder from your Mac to hersBoth Macs
No GitHub, no Terminal. Just a file transfer.

On your Mac: Finder → AirDrop in sidebar → wait for Bri's Mac to appear → drag the zip (or folder) onto her icon.

On her Mac: she accepts the AirDrop. It lands in her Downloads by default.

If AirDrop doesn't see her Mac Both Macs need Wi-Fi + Bluetooth on. AirDrop sidebar must be set to "Everyone" or "Contacts Only" (if you're contacts). Falling back: use a USB stick, iCloud Drive shared folder, or email the zip to her.
03Move the folder into Documents and unzip if neededHer Mac · Finder only
Documents is findable, predictable. Avoid Desktop clutter.

In Finder on her Mac:

  • If you sent the zip: she double-clicks it in Downloads → folder appears next to it
  • Drag the unzipped rallee-vault-for-bri folder from Downloads into Documents
  • Right-click the folder → Rename → change to rallee-vault (cleaner name)

Final location: ~/Documents/rallee-vault

04Open the folder in Claude CodeHer Mac
This is the moment everything comes alive.

Launch Claude Code. File → Open Folder → navigate to Documents/rallee-vault → Open.

Claude Code loads .claude/settings.json automatically (the file you pre-activated in PRE 02). Hooks and skills are now live for this folder only.

The first message in chat will trigger the session-state hook — Claude will load SOUL.md, CLAUDE.md, USER.md, LESSONS.md, MEMORY.md into context. You'll see a wall of text in Claude's first response. That's expected — it's how Claude knows the rules.

Populates USER.md. Persistent memory of who she is, what Rallee does, how she likes to work. After this, she never re-introduces herself.

Suggest she type something like this (encourage her to make it her own — this is just a starting frame):

"I'm Bri Hardie, founder of Rallee — a boutique recruitment and team-building agency in Sydney. I place senior talent into premium-positioned Aussie SMBs and scale-ups, and I help companies rally their teams around culture. I prefer direct, refined communication — no corporate buzzwords, no emojis in client comms, Australian register without 'mate'. Save this to my USER.md and remember it for every future session in this folder."

Claude updates USER.md. She's now "known" to this workspace.

06Demo the four core skillsBri types · You guide
First "oh, this is different from Claude Chat" moments. Pick the ones most relevant to her current work.

One prompt at a time. Let her experience each before moving on.

Demo A — Inventory:

"What's in this repo?" → /whats-shipped fires. Shows her toolkit in plain language.

Demo B — Brand bible:

"What does my brand bible say about voice?" → /brand-bible reads her voice rules verbatim. The refined/intelligent/warm + "rally" verb usage + anti-LinkedIn-template-prose stance.

Demo D — Critique:

Ask her for a recent LinkedIn DM or candidate email she sent. Have her paste it with "critique this". → /critique returns scored review with specific edits. The harsh-on-purpose feedback usually lands.

Tomorrow when she opens the folder, Claude remembers: "Bri onboarded yesterday, set up Rallee Starter, ran first design brief on LinkedIn placement win."

When we ship something worth pulling — new skill, fix, refined instructions — you'll:

  1. Pull the updates on your Mac (cd ~/Downloads/rallee-vault-for-bri && git pull origin main)

Don't introduce GitHub Desktop tomorrow. One thing at a time.
